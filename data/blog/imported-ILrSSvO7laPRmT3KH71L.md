- [ ] 1. - PM 不是功能清单的管理员，而是市场机会与公司资源的匹配者
- [ ] 2. - 前期（项目立项阶段）70% 时间放在战略论证
- [ ] 3. - 战术论证能让团队少走弯路、快速验证假设
- [ ] 4. - 小决策可以靠直觉，但任何的立项都不是小决策
- [ ] 5. - 成功的项目越多，就会积累“Credit”，从而调配团队中最强的人
- [ ] 6. - 失败的项目越多，会损失 Credit 让工程师打退堂鼓
- [ ] 7. - PM 学会珍视后 Credit，从而会重视打好基本功，做事稳准狠
- [ ] 8. - 当你有足够的 Credit，可以让你做事最终不需要再论证

从第一点来说 PM 更多时间应该投入在发现市场机会后的深度思考，有没有什么是适合我们做的 
从第二点来说，在把东西摆上台面的时候要先将各种可行性进行分析，script 的整个流程更多是我是我想重新设计 Agent 但是我只是觉得他 date out了，但是并没有很明确要往什么方向走，然后 script 的交互进一步强化了我的兴奋，然后后面将注意力花在让更多的人加入游戏，论证的阶段被我跳过了 从公司的流程上这不科学，容易在兴奋的过程中忽视掉很多致命的缺点

简单来说太依赖直觉了

最后你需要找到自己的产品流派，从目前创始人性格来说在 dify 比较合适的是走技术流派 然后对自己慢慢打磨技术视角
