目标导向: Agent 的行动是为了达成某个目标 (target)。
工具是手段: Function calling 是 Agent 实现目标、与外部世界交互并修改其状态的手段。
最终性: 如果一个任务需要多个步骤，例如“搜索信息 -> 汇总信息 -> 起草邮件 -> 发送邮件”，那么“发送邮件”这个 function call 就是针对“邮件已发送”这个最终目标实体的最后一次关键调用。如果只是“起草邮件”，那么生成邮件内容的调用就是关键。
正确性: 这个调用必须是成功的，并且其结果符合预期，才能被认为是“交付物”的形成。


复杂交付物可能涉及一系列关键调用:
比如生成一段复杂的代码，可能涉及到 create_file, add_function_stub, implement_logic_for_function, add_comments, run_linter 等多个调用。虽然最后一次可能是 save_file 或 commit_code，但之前的多个调用共同塑造了这个“代码段”交付物。在这种情况下，“交付物”是这些调用累积作用的结果。
“共同维护的交付物”的视角: 在你之前的图示中，左边的“编辑器”展示的是一个持续演进的交付物。每一次 Agent 的有效工具调用（不仅仅是最后一次）都可能在修改这个交付物。用户看到的是这个交付物从无到有，或从一个状态到另一个状态的演变。
交付物可能是“过程状态”而非“最终实体”:
有时，Agent 的交付物可能不是一个最终的实体，而是一个中间状态或一个可供用户进一步操作的基础。比如 Agent 帮助用户筛选出了3个最佳航班选项，这里的交付物是“包含3个航班选项的列表”，这可能是由 search_flights 和 filter_flights 等调用产生的，用户接下来可能会基于此进行选择。
